A.1. Data Collection and Query Parameters

The analysis compares Google Trends website exports with data collected using gtrendsR (version 1.5.2). The historical cutoff is September 8, 2026, the assignment date; the data were retrieved on November 26, 2026.

All four website queries used the same geography, category, and search type. The shorter query covers June 10–September 8, 2026; the two-term query removes Election; and the independent news query uses foldable iPhone. The latter was selected because the anticipated product announcement received Reuters coverage on September 8, 2026. Its peak is 100 in the week labeled September 6, 2026.

score <- function(x) as.numeric(ifelse(x == "<1", "0.5", x))

read_web <- function(file) {
  x <- read_csv(file.path(data_dir, file), skip = 2,
                col_types = cols(.default = col_character()))
  names(x)[1] <- "date"
  names(x) <- sub(": \\(United States\\)$", "", names(x))
  x |>
    pivot_longer(-date, names_to = "keyword", values_to = "hits") |>
    mutate(date = as.Date(date), value = score(hits))
}

read_r <- function(file) {
  read_csv(file.path(data_dir, file),
           col_types = cols(.default = col_character())) |>
    mutate(date = as.Date(substr(date, 1, 10)), value = score(hits))
}

align <- function(a, b) {
  inner_join(select(a, date, keyword, hits, value),
             select(b, date, keyword, hits, value),
             by = c("date", "keyword"), suffix = c("_a", "_b")) |>
    mutate(difference = value_b - value_a,
           changed = hits_a != hits_b)
}

A.2. Exploring the Website Data

The five-year export contains 262 weekly observations per term (September 5, 2021–September 6, 2026). The shorter query contains 91 daily dates. The weekly labels identify the start of each week, not the exact query boundaries. A score of 100 indicates peak relative search interest within a query; 0 indicates insufficient relative search interest to report a nonzero score, not necessarily zero searches. Google normalizes sampled searches by total searches and rescales the resulting shares (Google Trends documentation). Values reported as <1 are coded as 0.5 for numerical summaries only.

A.3. R Collection and Measurement Validity

The original script uses Harris rather than Kamala Harris. Holding the other two terms and query settings constant, the series differ in all 262 weeks. Harris has a peak of 11 versus 7 for Kamala Harris, a mean difference of +0.597 index points, and a Pearson correlation of 0.972. A surname is an imperfect proxy for a specific political figure because it can also refer to other people, places, and organizations; the index differences do not identify the share of unrelated searches.

A.4. Comparing the Two Methods

The website and R series match on all 786 date–term pairs, with no difference in either direction. The repeated R queries also yield identical values. The final repeat began 2 minutes and 28 seconds after the first query. This demonstrates short-term stability in these pulls, not guaranteed reproducibility: the underlying sampled searches, normalization, and service-side caching may change.

Show R code 
compare <- function(a, b, label) {
  x <- align(a, b)
  stopifnot(nrow(x) == nrow(a), nrow(x) == nrow(b))
  data.frame(Comparison = label, Matched = nrow(x),
             Identical = sum(!x$changed),
             `Mean difference` = mean(x$difference),
             MAE = mean(abs(x$difference)),
             `Max absolute difference` = max(abs(x$difference)),
             check.names = FALSE)
}

Dimension Website R (gtrendsR)
Reproducibility Manual downloads must be archived. Scripts reproduce query settings, not necessarily identical samples; cache the raw pulls.
Provenance CSV records terms, geography and category, but not all settings or retrieval time. Returned columns record query parameters; the script separately logs the actual retrieval time.
Scale Manual repetition is slow. Batch collection is easier, but queries with many terms require overlapping batches and a common anchor for comparable scores.
Fragility Download errors, changed UI, or incorrect filters may go unnoticed. Unofficial endpoint changes, rate limits, or incomplete results can break queries; check errors, dates, keys, and row counts.

Conclusion. Google Trends is useful for measuring relative search attention, but results depend on the search terms, query window, geography, normalization, and sampling. Archived raw data and recorded parameters are essential for reproducible research.

Supplementary R code and historical plots

The following collection code reproduces the query design. The actual data are cached as CSV and RDS files. It is displayed as reference code only; rendering this report does not rerun the Google Trends requests. The three repeat calls were executed separately at the recorded times.

library(gtrendsR)
library(readr)

data_dir <- "data/assignment02_sep08"
dir.create(data_dir, recursive = TRUE, showWarnings = FALSE)
time_5years <- "2021-09-08 2026-09-08"
time_all <- "2004-01-01 2026-09-08"

collect_trends <- function(filename, ...) {
  path <- file.path(data_dir, filename)
  if (file.exists(paste0(path, ".rds"))) {
    return(readRDS(paste0(path, ".rds")))
  }
  pulled_at <- Sys.time()
  result <- gtrends(...)
  saveRDS(result, paste0(path, ".rds"))
  write_csv(result$interest_over_time, paste0(path, ".csv"))
  writeLines(format(pulled_at, tz = "America/Chicago", usetz = TRUE),
             paste0(path, "_retrieval.txt"))
  result
}

us_query <- function(filename, terms) {
  collect_trends(filename, keyword = terms, geo = "US",
                 time = time_5years, gprop = "web", category = 0,
                 onlyInterest = TRUE)
}
