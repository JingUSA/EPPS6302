2. GovInfo API: collections, search, packages and pagination

The GovInfo API documentation was used to construct requests. The Congressional Hearings collection endpoint /collections/CHRG/2026-01-01T00:00:00Z returned HTTP 200. The Search API used the identical query and descending publishdate order, with 100 records per page. Passing the first response’s offsetMark into the next request retrieved a second page of 100 records; the two pages had no overlapping package IDs. Only two pages were tested because the assignment required ten documents, not an exhaustive collection.

# Extract scalar fields rather than coercing unequal-length nested arrays.
scalar <- function(x) {
  if (is.null(x) || length(x) == 0L) return(NA_character_)
  as.character(x[[1]])
}
api_top10 <- purrr::map_dfr(found$results, function(x) {

3. Download and comparison

Following the bulk-download approach in govtdata01.R, the ten PDFs were downloaded from the website export and independently from the API granule links. Requests were made sequentially with a randomized one-to-three-second interval for uncached PDF downloads. Files were stored in separate, Git-ignored folders under data/assignment05/. Valid cached files were reused on subsequent runs. Each download was checked using pdftools::pdf_info(), file size and an MD5 checksum.

4. Document usability and methodological reflection

4.1. PDF text extraction

All ten documents could be processed using pdftools::pdf_text(). Text was extracted from 434 of 444 pages (97.75%). Ten pages yielded no text, and 85 pages (19.14%, including the ten empty-text pages) contained fewer than 100 characters after whitespace normalization. The total approximate whitespace-delimited token count was 184,135. These counts describe extraction coverage, not transcription accuracy or substantive word counts.

  empty_pages = sum(chars == 0), low_text_pages = sum(chars < 100),
  approximate_tokens = sum(str_count(pages, "\\S+")))

Poppler reported ligature-parsing diagnostics while extracting text, although all ten extractions completed. These warnings indicate possible character-encoding problems and should not be ignored when assessing text quality. Low-text pages may include blank pages, figures, tables or scanned material; the extraction counts alone cannot distinguish these categories. The PDFs are usable as a starting point for a corpus, but a reliable analysis would require checking reading order, removing repeated headers and page numbers, separating testimony from questions and appendices, and identifying speakers. OCR should be considered only for pages verified to contain relevant text that is not otherwise extractable. A structured table could use one row per hearing or per speaker turn, with the package ID as a stable linking key.

4.2. Improvements

For document-level variables such as title, date, committee and identifiers, the API metadata is preferable to parsing PDF cover pages. All ten granule summaries advertised text downloads (txtLink), and all ten website-export records included HTML links. These alternatives should be tested before additional PDF parsing or OCR; their text quality was not assessed in this run. MODS metadata can provide further structured bibliographic information, PREMIS describes preservation information, and ZIP packages support archival acquisition. A scalable workflow would cache raw responses, retain query and retrieval timestamps, paginate using the returned cursor, log failures and validate unique identifiers and checksums. It would also distinguish hearing dates from modification dates and inspect changes to existing records.

4.3. API versus manual search and web scraping (two sentences)

The API provided a reproducible structured query, cursor-based pagination, stable identifiers, and package- and granule-level metadata without relying on the website’s manual export limit. Unlike last week’s HTML scraping, API-based collection did not depend on visual page structure or CSS selectors, although nested JSON fields and the distinction between packages and granules still required explicit handling.
