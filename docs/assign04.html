cache_html <- function(url, path, agent, time_path) {
  if (!file.exists(path)) {
    Sys.sleep(2)
    response <- httr::GET(url, httr::user_agent(agent), httr::timeout(60))
    httr::stop_for_status(response)
    writeBin(httr::content(response, as = "raw"), path)
    writeLines(format(Sys.time(), tz = "America/Chicago", usetz = TRUE),
               time_path)
  }
}

2. Wikipedia tables and data cleaning

The foreign-exchange reserves page contains two wikitable elements. The country-level table has 198 rows and eight columns, including two repeated header rows after the first header. The second table describes global reserve currency composition and is not the target.

The first table was cleaned by removing the extra headers, reference markers and nonbreaking or thin spaces, dropping the change, excluding-gold and reference columns, and checking for aggregate rows. No aggregate row remained among the 196 entries. The reserves including gold column is converted from USD millions to USD. Country labels with trailing asterisks are preserved in the raw data and cleaned separately for matching.

Show R code 
clean_text <- function(x) {
  x |> as.character() |> str_remove_all("\\[[^\\]]*\\]") |>
    str_replace_all("[\u00a0\u2009\u202f]", " ") |> str_squish()
}

# Strict day-month-year parser: do not guess between date orders.
strict_dmy <- function(x) {
  p <- str_match(x, "^([0-9]{1,2})\\s+([[:alpha:]]+)\\s+([0-9]{4})$")
  mm <- match(str_to_lower(str_sub(p[,3], 1, 3)), str_to_lower(month.abb))
  iso <- rep(NA_character_, length(x))
  good <- !is.na(p[,2]) & !is.na(mm) & !is.na(p[,4])
  iso[good] <- sprintf("%04d-%02d-%02d", as.integer(p[good,4]),
                      mm[good], as.integer(p[good,2]))
  result <- as.Date(iso, format = "%Y-%m-%d")
  ok <- !is.na(result) & !is.na(iso)
  bad <- which(ok & format(result, "%Y-%m-%d") != iso)
  result[bad] <- NA
  result
}

clean_reserves <- function(x) {
  stopifnot(ncol(x) == 8, grepl("Including gold", x[[3]][1], ignore.case = TRUE))
  names(x) <- c("country", "continent", "reserves_including_gold",
                "change_including_gold", "reserves_excluding_gold",
                "change_excluding_gold", "reported_date", "reference")
  x |> slice(-(1:2)) |> mutate(across(everything(), clean_text)) |>
    filter(!is.na(country), country != "",
           !str_detect(country, regex("^(World|Total|Grand Total|World Total|European Union|Euro Area|Eurozone)$",
                                      ignore_case = TRUE))) |>
    transmute(country, continent,
              reserves_usd_million = parse_number(reserves_including_gold),
              reserves_usd = reserves_usd_million * 1e6,
              reported_date_raw = reported_date,
              reported_date = strict_dmy(reported_date_raw),
              reported_year = as.integer(str_extract(reported_date_raw, "\\b(?:19|20)\\d{2}\\b")))
}

When to scrape: Web scraping is appropriate when the information needed is available only through accessible web pages, automated retrieval is permitted, and a documented API or bulk download cannot meet the research need. When a structured API or official download provides the required data, it is preferable because the schema and provenance are easier to validate and the collection process is less vulnerable to changes in page layout.

4. Research Data Plan: Public Disclosures of Cyber Espionage

Source and rationale. The proposed source is the Council on Foreign Relations Cyber Operations Tracker, which catalogues publicly known suspected state-sponsored cyber operations since 2005. The research examines whether public disclosures of cyber espionage affect political trust. CFR provides incident classifications and attribution information, making it more directly relevant than an unclassified collection of cybersecurity news. It does not cover all incidents: publicly disclosed events are a selected subset, and its methodology describes attribution uncertainty and English-language reporting bias.

Permission and access. CFR’s Terms of Use provide free access but restrict certain uses and public or commercial redistribution of protected content. Access to the public site is not blanket permission to scrape or republish it. The current robots.txt could not be independently retrieved during preparation of this plan, so permission for automated access is not established. Before making any automated request, the exact target path and host (including the download host) would be checked and the result archived. Any unclear use or redistribution rights would be clarified with CFR. No CFR pages are scraped in this assignment.

API and collection strategy. The tracker offers an official bulk download. No documented public API was identified on the tracker or in the reviewed materials. The official download is therefore the primary acquisition method; scraping would only be considered for essential missing fields, such as disclosure dates, if automated access and the intended use are permitted. Dates of occurrence and public disclosure would be coded separately; records without verified disclosure dates would be flagged rather than assigned arbitrary dates.

Volume, rate limiting and caching. The initial acquisition requires one official download, with quarterly checks for updates consistent with CFR’s stated update schedule. If approved supplemental page requests are necessary, only unmatched records would be visited, sequentially, at no more than one request every five seconds, using a descriptive user agent. HTTP 429 or 503 responses would trigger a pause and observance of Retry-After; repeated failures would stop collection. Original files, retrieval timestamps, URLs, checksums, variable definitions and data-processing code would be archived. Public release would be limited to materials authorized for redistribution.

Failure detection. Required fields, unique incident identifiers, date formats, country mappings and row counts would be tested before analysis. Changes in column names, missingness, duplicate records or unexpected changes in coverage would stop the workflow for manual review. New versions would be compared against earlier snapshots to identify revised attribution or dates, retaining both versions and a change log. A sample of disclosure dates would be checked against original public reports. Downstream models would use a frozen, documented snapshot rather than a continuously changing website.
